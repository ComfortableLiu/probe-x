## Event Sync Feature Implementation

### Problem
Events reported by SDK clients that don't exist in `meta_event` MySQL table are invisible in the event management page.

### Solution: On-demand Discovery + Manual Registration
Query ClickHouse `event_log` for distinct `$event_name` in last 7 days, diff against MySQL `meta_event`, merge and display in UI with source tags. Users can "补充信息" to register unregistered events.

### Files changed (9 files, +269/-33):
**Backend (data-dashboard-api-service):**
- `event.module.ts` — Added `ClickHouseModule` import

### Bugs found & fixed post-implementation:
1. **ClickHouse SQL missing backticks** — `$event_name` and `$service_time` must be wrapped in backticks (project convention for `$`-prefixed columns)
2. **MySQL pagination bug** — Original code did DB-level `skip/take` then tried manual merge, losing data beyond page 1. Fixed: when `needMerge=true`, use `getMany()` (no skip/take), fetch all then manual paginate
3. **Missing source filter** — Plan specified a source SELECT filter but it wasn't implemented. Added with `useQuery` hook for URL query param binding

### Key technical notes:
- ClickHouse column names with `$` prefix MUST use backticks in SQL: `` `$event_name` ``
- `ClickHouseModule` from `@probe-x/shared-utils/src/lib/backend-common` must be imported into any NestJS module needing ClickHouse access
- `ClickHouseService.query<T>(sql, params?)` is the query interface
- All code changes done via Claude Code CLI (user's strict requirement: "严禁你自己改代码")
